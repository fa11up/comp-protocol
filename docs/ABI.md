# ABI integration

The JSON files in `docs/abi/` contain complete Solidity ABI arrays, including constructor inputs, functions, events, and custom errors. All token, collateral, debt, and credit amounts are uint256 **minor units with 18 decimals**; `1 ether` in Solidity examples means 10^18 units, not an ETH payment. All constructors and state-changing methods are nonpayable. There is no payable fallback or receive function.

`LaunchToken()` takes no constructor arguments and mints exactly 10^27 minor units to its deployer. Its metadata is `COMP Launch` / `CPL` / 18 decimals. Its public functions are only the standard ERC-20 views, transfers, and approval; it has no mint/burn or administration API. Use `docs/abi/LaunchToken.json` for the launch asset and `docs/abi/CompToken.json` for the stablecoin borrowed from CDPVault.

The token and oracle constructor signatures are `MockIMD()`, `CompToken(address vault)`, and `MockWorkOracle(address vault)`. `CompToken(0x0)` defers the one-time `setVault`, while a nonzero vault is validated (or recognized as the creating contract) and locked at construction. MockIMD starts with zero supply and metadata `Identity MD` / `IMD`; CompToken starts with zero supply and metadata `Compute Money` / `COMP`. Neither has a configured supply cap. MockWorkOracle requires a deployed vault or its creating contract and permanently limits rights consumption to that address.

`CDPVault(address imdToken, address compToken, address oracle, address priceFeed, address nhiFeed, address spotFeed)` requires a deployed IMD token and three deployed, distinct feed contracts. The sixth address is the only new constructor argument; divergence, marker share, and stability fee come from `src/DeploymentConfig.sol`. Zero COMP creates a fresh `CompToken(address(this))`, immediately bound to the vault; a nonzero COMP must have code and differ from IMD. Any identical feed addresses revert `InvalidFeed`. Zero oracle creates and binds a fresh MockWorkOracle; a supplied oracle must answer `mintingRights(address)` and, if it exposes `vault()`, name this vault. An existing, uninitialized CompToken must separately authorize the vault through its reciprocal `setVault` check before borrowing or work minting can succeed.

With both COMP and oracle zero, construction closes both links: no post-deployment initialization transaction is needed or available, and `CompToken.setVault` reverts `AlreadyInitialized` for every caller from genesis. The oracle is immutable; this vault has no `setOracle` or parameter setter. The requester retains no initialization authority, and the operator retains only the MockIMD and MockWorkOracle test faucets. Feeds still require an accepted update through their configured reporter or attestation path before feed-dependent vault operations.

Deferred CompToken initialization and mock faucet authority is the explicit workflow operator `0x5167D014a056E43883e1BBEa5530c3c0dC993281`, pinned in `src/DeploymentConfig.sol`. The mock `deployer()` getters return that operator even when a factory or the vault creates the contracts. The factory and transaction origin gain no permissions.

`SwarmFeed` is abstract. `PriceFeed`, `NhiFeed` and `SpotFeed` are the concrete artifacts the manifest deploys. Each constructor takes only `(uint256 maxAge_, uint256 maxDeviationBps_)`, which `launch.json` supplies as 86400/2000, 86400/2000 and 3600/2000; the attester, relayer, payload chain id, answer type, three reporters and quorum are constants in `src/DeploymentConfig.sol`, forwarded to the abstract constructor, which still refuses a zero attester, duplicate reporters, a quorum outside one to the number of nonzero reporters, a zero maxAge or a maxDeviationBps above 10,000. A nonzero relayer is the sole permitted attestation submitter; the pinned relayer is nonzero. No setter or administrator can change the configuration, and no subclass adds application-specific value bounds. Each feed pins its own oracle question: `expectedQuestionHash(fromBlock, toBlock)` returns the questionHash the feed accepts for a window (zero only on a feed that pins none), `lastToBlock()` is the newest accepted window end, and an attestation is refused with `WrongQuestion(expected, given)`, `WindowSpanOutOfRange(span)` (PriceFeed allows 300 to 1200 blocks, NhiFeed and SpotFeed 150 to 1200), `WindowNotAdvancing(toBlock, lastAccepted)` or `InvalidWindow` before anything is consumed. A feed with no pinned question could not be constructed without a relayer (`UnboundQuestionNeedsRelayer`), and one with a question needs a positive, ordered span (`QuestionNeedsWindowBounds`). `docs/abi/PriceFeed.json`, `docs/abi/NhiFeed.json` and `docs/abi/SpotFeed.json` carry all of these members.

Feed values use 18 decimals. Before the first update, `latestValue()` returns `(0, 0)` and `isStale()` is true. A value is stale only when its age is greater than maxAge, so the exact age boundary is still fresh. Zero updates revert. While the previous value is fresh, each submitted report and accepted update must differ by at most `floor(previousValue * maxDeviationBps / 10000)`; once stale, the next update may re-anchor at any positive value. Reaching reporter quorum publishes the median (the floored mean for quorum two), dated at the oldest contributing report. An unfinished round expires after maxAge. A quorum-one reporter can complete multiple rounds in the same block; the deviation bound is per update, not per unit of time.

`submitAttestation` takes an `OracleAttestation` tuple in this exact order: `(bytes32 requestId, uint256 chainId, bytes32 questionHash, uint8 answerType, bytes answer, uint256 figure, uint64 fromBlock, uint64 toBlock, bytes32 blockHash, bytes32 panelJobId, uint64 issuedAt, uint64 expiresAt)`, followed by a 65-byte signature. The EIP-712 domain is `IdentityMD Oracle`, version `1`, with the deployment chain ID and the receiving feed's address, computed once in its constructor. Payload chainId and answerType must equal `attestationChainId()` and `attestationAnswerType()`; the payload data chain may differ from the consumer chain (for example, mainnet data consumed on Sepolia). requestId is consumed once per feed; issuedAt cannot be in the future, exceed expiresAt, precede the last accepted update, or be older than maxAge. Delivery after expiresAt is rejected. The feed publishes figure and uses signed issuedAt for freshness, then discards any unfinished reporter round.

The signed questionHash binds a changing pinned block window and is emitted with each accepted attestation; there is no immutable questionHash gate or getter. The contract cannot verify which question was answered. Once seeded and while the last value is fresh, the deviation guard bounds a wrong-question figure. A nonzero relayer covers the unseeded first value and stale re-anchors. The consumer domain prevents cross-feed replay but does not identify the question; a stable per-question identifier would remove the need for a relayer entirely.

The vault treats primary price as COMP per IMD scaled by 1e18. `collateralRatio` is `floor(collateral * price * 100 / (debt * 1e18))`, using accrued debt. Only NHI determines requirements: at or below `0.60e18`, minCR is 200% and grace is zero; at or above `0.85e18`, minCR is 150% and grace is six hours. Between these points, minCR is `150 + ceil((0.85e18 - nhi) * 50 / 0.25e18)` and grace is `floor((nhi - 0.60e18) * 21600 / 0.25e18)` seconds. These views read latest values without enforcing freshness. Borrowing, work minting, withdrawals with debt, marking, clearing recovered marks, and liquidation still require primary and NHI feeds fresh and primary price nonzero.

Borrowing, withdrawals with debt, marking, and liquidation additionally require a fresh, nonzero spot price with `abs(primary - spot) <= floor(primary * maxDivergenceBps / 10000)`. The exact boundary passes. The primary is a window average; spot only checks disagreement and never determines valuation. A pinned closing block and an attestation valid for its TTL let an attacker target a known block and use the signature later, motivating this independent sanity bound. Work minting and clearing recovered marks retain their original primary/NHI guards. Deposits, repayment, and debt-free withdrawals remain available with stale or diverging feeds.

The stability fee is an annual, immutable rate with a zero default. `debtIndex()` is `1e18 + floor((block.timestamp - deployedAt) * stabilityFeeBps * 1e18 / (365 days * 10000))`. Before borrowing, repayment, or liquidation changes debt, the vault checkpoints unpaid fees as `floor(principal * (debtIndex() - debtIndexOf(account)) / 1e18)` plus earlier unpaid fees, then records the current index. Fees do not themselves earn interest. Views compute the same accrual without changing the checkpoint; deposits, withdrawals, and marking do not capitalize fees. `positions(account)` preserves its two-value ABI but returns full accrued debt, as does `debtOf(account)`; `stabilityFeeOf(account)` returns only its unpaid fee component. `totalDebt()` and the existing debt ceiling continue to track minted principal.

Both repayment paths pay fees first and principal second. They burn the full requested COMP amount, mint the paid fee portion to `feeRecipient()`, and increase `totalFeesMinted()` by that portion. Unpaid fees create no token supply. Amounts above accrued debt still revert `ExcessRepayment`; zero-fee deployments perform the original burn without fee minting.

## Redemption channel A

`redeem(uint256 amount, uint256 minImdOut, address candidate)` returns `uint256 imdOut`. It burns exactly the caller's amount and pays only IMD. `amount` and `minImdOut` use 18 decimals. No allowance is required. The operation requires fresh primary, NHI and spot feeds, price agreement, and a valid denominated price; ParameterizedVault also requires its Chainlink USD leg. Its price is USD per IMD, so COMP redeems at one dollar less the fee. Plain CDPVault retains its original primary-feed denomination and has no Treasury reserve.

The vault computes `floor(amount * (10000 - feeBps) * 1e14 / price)` once, independent of the candidate. It spends up to this amount from the Treasury's actual IMD balance, including IMD not listed in the reserve valuation register. When that covers the payout, the candidate is ignored and no position changes. Otherwise it empties the Treasury's IMD, then cancels `amount - floor(reserveOut * price / ((10000 - feeBps) * 1e14))` of the candidate's accrued debt and releases the remaining payout from that position. Conservative rounding ensures every released wei is covered by cancelled debt. One candidate must cover the entire shortfall; there is no partial fill or sorted list.

The candidate must have debt and a ratio strictly below `redemptionCeilingCR() = minCR() + redemptionSpread()`. At the shipped spread of 50 this ceiling ranges from 200 to 250 as NHI falls. The spread alone is governed, between 25 and 100 inclusive through the existing governor, pending slot and 48-hour delay. `Change.RedemptionSpread` is appended as enum value 4. `pendingRedemptionSpread()` returns its payload and eta; anyone may apply a matured proposal. The exact ratio check is `positionOut <= floor(collateralBefore * debtCancelled / accruedDebtBefore)`, so even deeply underwater positions cannot be made worse. Full debt cancellation leaves unused collateral owned by the borrower.

`redemptionFeeBps(amount)` includes the proposed burn's rate increase. The base is a 1e18-scaled fraction, decays per elapsed second by `999983955055097432 / 1e18` (approximately a twelve-hour half-life), and increases by `floor(amount * 1e18 / priorSupply) / 4`, where `priorSupply` is the pre-burn supply less any principal minted earlier in the same transaction (a burn with nothing before it saturates at the cap). Stored base is capped at 4.5%; the charged fee is 50 plus its basis points rounded **up** to a whole one, at most 500. Both fee bounds are source constants with no setters. A zero-amount quote returns the floor plus the currently decayed base, including when supply is zero. For example, burning 10% of supply from a zero base costs 300 basis points, and 0.39 of a 1000 supply costs 51. Fractional basis points remain in the stored base, so a half-life observation can differ by one basis point through rounding. Every successful call checkpoints the base and timestamp; reverted calls change neither.

The stored base excludes the part of a position-funded burn that cancelled principal the candidate minted within the last twelve hours (one half-life), tracked per position and retired by any repayment, liquidation or redemption; that part is still charged the full quoted fee, which stays in the candidate's own collateral. A borrower who mints, redeems against themselves and withdraws therefore cannot move the rate others pay unless the debt was held in the eligible band for the window first.

The redemption fee is never transferred or minted: the discount stays as backing. Candidate debt cancellation remains fees-first, but redemption does **not** remint cancelled stability fees. Existing repayment and liquidation fee distribution is unchanged. Supply accounting is now `totalSupply = totalDebt + totalWorkMinted - totalNonPrincipalRedeemed`; the last counter records reserve-funded burns plus burns cancelling previously unminted stability fees. `totalWorkMinted`, consumed rights and `totalFeesMinted` are unchanged by redemption. Reserve spending lowers the reserve term of `workCeiling`, and cancelling principal lowers its debt term through the existing transaction snapshot accounting.

Every route also checks aggregate backing before burning or paying out, measured on the state the call found (before the candidate changes) and enforced after the candidate's own eligibility and ratio checks. Backing is the vault's secured collateral plus, on ParameterizedVault, the Treasury's IMD balance valued at the redemption price (listed or not, and whatever retained factor the register gives it) plus the registered value of every other listed reserve asset. Secured collateral is the vault's IMD balance less anything deposited earlier in the same transaction, valued at the redemption price and capped at `minCR()` percent of the principal that existed before the transaction (less `totalBadDebt()`): collateral posted against no debt, and surplus above what the health rule holds in place, backs no COMP and does not count. The value released must be at most `floor(backing * amount / preBurnSupply)`, otherwise `RedemptionWorsensBacking` reverts the entire call. This protects remaining COMP after a permitted debt unwind or reserve withdrawal leaves work-issued supply underbacked; a fee alone does not guarantee an improving ratio in that state. It does not change the mint-time work ceiling or the feed-priced payout. Existing backing is rounded down and the outgoing value up, so fractional-value dust cannot conceal a loss; a marginal dust-sized redemption can be conservatively refused. The guard uses circulating supply as it stands, excluding accrued unpaid fees, and applies to reserve-only, borrower-only and mixed payouts; a mint earlier in the same transaction therefore only tightens it.

`Redeemed(redeemer, candidate, compBurned, imdOut, reserveOut, debtCancelled, feeBps)` indexes the first two addresses. `MinimumOutNotMet` rejects a payout below the caller's minimum; `IneligibleRedemptionPosition` rejects debt-free candidates or ratios at/above the ceiling; `RedemptionWorsensRatio` rejects a worsening exact ratio; `ExcessRepayment` rejects amounts above supply or candidate debt. A zero input or zero rounded payout reverts `ZeroAmount`. Token balance and existing oracle errors also propagate. Every failure rolls back the burn, rate, Treasury accounting and position changes together.

For integration, read `redemptionFeeBps(amount)`, `redemptionReserve()`, the USD price and the candidate's accrued debt and ratio; then submit `redeem` with a slippage-protected minimum. A prior quote is not a guarantee: intervening redemptions, elapsed time, feed updates or governance may change execution. The constructor signatures and the four manifest artifacts are unchanged; no post-deploy setup is added. Persistent regression checks are in `script/checks/Redemption.t.sol`, runnable with `FOUNDRY_TEST=script/checks forge test --offline --match-contract RedemptionTest`.

## Compute backing: Treasury, UsdPriceFeed and the work ceiling

`ParameterizedVault(address imdToken, address compToken, address oracle, address priceFeed, address nhiFeed, address spotFeed)` has the same constructor as CDPVault and creates three contracts inside it: `Parameters`, `Treasury` and `UsdPriceFeed(priceFeed)`. None can be passed in, so a launch manifest still names four contracts and makes no post-deploy call. On this vault `feeRecipient()` is the Treasury: every liquidation's protocol cut (IMD) and every paid stability fee (COMP) is transferred or minted there, never to an account. `Treasury.sync(token)` turns an arrival into a recorded receipt; `withdraw` is the approved operator's alone and takes its destination as an argument.

`UsdPriceFeed` is an `ISwarmFeed`. `latestValue()` is the IMD/ETH primary feed's value multiplied by Chainlink ETH/USD (`0x694AA1769357215DE4FAC081bf1f309aDC325306` on Sepolia, pinned in `DeploymentConfig.sol` as `CHAINLINK_ETH_USD`), divided by the aggregator's decimals, so it is USD per IMD scaled by 1e18, dated at the older of the two legs. `isStale()` is true if the IMD/ETH feed is stale or the ETH/USD answer is non-positive, missing, or older than `ETH_USD_MAX_AGE` (one day). `maxAge()` is the shorter leg. An unreachable aggregator reads as stale rather than reverting. `ethUsdPrice()` exposes the ETH/USD leg on its own, USD per ETH scaled by 1e18, zero under the same conditions that make the leg stale; the vault uses it to bring the Treasury's USD figure into its own unit.

The Treasury's reserve register holds, per listed asset, an `ISwarmFeed` price source (USD per whole token, 1e18-scaled), a `haircutBps` and the token's `decimals`. `haircutBps` is the retained-value factor: the asset counts for `haircutBps / 10000` of `balance * price / 10^decimals`. Both endpoints are valid: zero counts for nothing and 10000 counts in full; a lower factor reduces the backing credited to a volatile asset. `reserveValueUsd()` is the sum over listed assets; an asset whose price source is stale, reads zero, or reverts on either read counts for nothing, so a dead feed can only lower the figure and never makes the view revert. COMP can never be listed: `validateReserveAsset` and `setReserveAsset` revert `CompIsNotReserve` for the creating vault's `compToken()` before anything else is checked. Other refusals are `InvalidReserveAsset` (zero or code-less asset, or one whose `decimals()` exceeds 77), `InvalidPriceSource` (a feed without code, or one that does not answer `isStale()` and `latestValue()` with well-formed words), `HaircutOutOfRange` (above 10000, or a nonzero haircut on a delisting) and `NotAReserveAsset` (delisting something not listed). Changes emit `ReserveAssetSet(asset, priceFeed, haircutBps)` or `ReserveAssetRemoved(asset)`.

There is no owner path to the register. `setReserveAsset` accepts calls only from `registrar()`, which the Treasury resolves as its creating vault's `parameters()`; a Treasury created by anything without one has a zero registrar and a register that stays empty. Listing, repricing and delisting therefore all go through `Parameters.proposeReserveAsset(asset, priceFeed, haircutBps)` (a zero `priceFeed` delists): governor-only, validated by the Treasury's own rules at proposal so a refused listing never occupies the slot, public for the 48-hour `TIMELOCK`, and applied by anyone through `applyPending()`. The same slot carries `propose(ParamSet)` and `proposeWorkRatio(bps)`; `pendingChange()` returns the kind (`Economics`, `WorkRatio`, `ReserveAsset`) and eta, and `pendingSet()`, `pendingWorkRatio()` and `pendingReserveAsset()` each return their payload only when the pending change is of their kind (zero eta otherwise). Only one change of any kind waits at a time.

`workRatioBps()` ships at 2500 (`WORK_RATIO_BPS`). `proposeWorkRatio` reverts `WorkRatioTooHigh(bps)` above `MAX_WORK_RATIO_BPS`, a constant 2500, so governance can lower the ratio and never raise it: 5000 is where worst-case backing with an empty reserve touches one at the loosest NHI, and the cap is half of it (section 3 of `COMPUTE-BACKING-DESIGN.md`). `workCeiling()` is `reserveValue() + backedDebt() * workRatioBps() / 10000`, both terms in the vault's own unit of account, which is the primary feed's: wei of ETH per IMD, so one COMP of debt is one ETH-worth of collateral to `minCR` and `liquidate`. `reserveValue()` is `reserveValueUsd()` divided by `UsdPriceFeed.ethUsdPrice()`, zero while that leg is stale; for IMD priced through the vault's own `UsdPriceFeed` the ETH/USD leg cancels and the reserve is worth `balance * primary price * haircut`, which is what the vault would lend against. `backedDebt()` is `totalDebt()` capped at the value it had when the current transaction began (debt created in the same transaction counts for nothing, so a borrow / work-mint / repay / withdraw round trip in one call is refused at the work mint) and less `totalBadDebt()`, saturating at zero (the residual principal of a drained position stands for no collateral). `mintFromWork(amount)` reverts `WorkCeilingReached` when `totalWorkMinted() + amount` would exceed the ceiling, after the rights check and before any state changes, so a refused mint consumes no rights; because a finite ceiling is priced off the primary feed, it also reverts `PriceDivergence` or `StaleFeed` under the same spot-feed conditions as `mintCOMP`. The ceiling gates new work minting only: repayment across transactions, a reserve withdrawal or a falling price can leave `totalWorkMinted()` above it, which simply stops further work minting until backing returns. On the plain `CDPVault`, `workCeiling()` is uint256.max, `mintFromWork` does not consult the spot feed, and `feeRecipient()` is FEE_RECIPIENT, exactly as before.

These paths are exercised by `script/checks/ComputeBacking.t.sol`, run with `FOUNDRY_TEST=script/checks forge test --offline --match-contract ComputeBackingTest`; a liquidation there shows both revenue streams arriving in the vault's Treasury.

An active mark preserves its original grace snapshot and marker address. Liquidation is allowed from `markedAt + grace` through `markedAt + grace + liquidationWindow()`, inclusive, while the position remains unhealthy; after that the mark must be retaken and grace restarts. The window remains the shorter primary/NHI maximum age. Payout is exactly `floor(debtToRepay * 1.1e18 / price)` IMD minor units, and the position must cover the full payout. Successful borrowing and withdrawals clear marks; deposits, repayment, and liquidation clear them on observed recovery (or zero debt). Anyone can call `clearRecoveredMark` to record recovery from a feed change. An unobserved recovery followed by another fall does not reset grace within the mark's bounded lifetime.

Liquidation bonus is the full payout minus `floor(debtToRepay * 1e18 / price)`. Marker and protocol each receive their basis-point share of this same bonus, rounded down. The liquidator receives the remainder including principal; if the marker is the liquidator, their payments use one combined transfer. The sum of marker and protocol shares cannot exceed 10,000 basis points. Neither share increases the borrower's collateral loss. The existing `Liquidated` event reports total collateral seized, including all recipients' shares; the marker is available from `liquidationMarks` while the mark remains stored.

`badDebtOf(account)` measures accrued debt exceeding what collateral can cover at the current primary price, including the full 10% liquidation payout and its exact integer rounding. For positive collateral, repayable capacity is `ceil((collateral + 1) * price / 1.1e18) - 1`; uncovered debt is any excess above capacity. An exhausted position reports all remaining debt. This view does not enforce freshness. `totalBadDebt()` records residual accrued debt when liquidation exhausts collateral and refreshes that record during repayment of an exhausted position, including newly accrued fees. Depositing collateral does not erase the record; after a deposit, actual repayment reduces the historical residual only when remaining debt falls below it. The accumulator is a record at its last updates, not a continuously repriced sum of `badDebtOf`. These APIs provide measurement only: no insurance, debt forgiveness, or change to the full-payout guard.

Events:

- All three tokens emit standard `Transfer` and `Approval`; mint/burn use the zero-address convention. LaunchToken emits its only mint during construction.
- CompToken emits `VaultSet(vault)` with indexed vault once, during construction or the one-time `setVault`.
- MockWorkOracle emits `RightsGranted(account, amount)` and `RightsConsumed(account, amount)` with indexed account.
- SwarmFeed and both subclasses emit `ValueUpdated(value, updatedAt)`, `Reported(round, reporter, value)` with indexed round and reporter, and `AttestationAccepted(requestId, questionHash)` with indexed requestId and the accepted pinned-window hash in event data.
- CDPVault emits `OracleSet(oracle)`, `CollateralDeposited(account, amount)`, `CollateralWithdrawn(account, amount)`, `COMPMinted(account, amount)`, `WorkMinted(account, amount)`, and `COMPRepaid(account, amount)` with indexed addresses.
- `UnderwaterMarked(owner, markedAt, grace)` and `UnderwaterMarkCleared(owner)` index owner.
- `Liquidated(owner, liquidator, debtRepaid, collateralSeized)` indexes owner and liquidator. Actual payout is included, so consumers need not reconstruct rounded amounts.

Custom errors have no arguments unless indicated in the generated ABI. `Unauthorized` indicates a caller outside the permitted authority; `AlreadyInitialized` indicates permanently closed CompToken setup. Invalid contract addresses, and targets that fail the reciprocal-link checks, produce `InvalidToken`, `InvalidVault`, `InvalidOracle`, or `InvalidFeed`. A failed `setVault` does not consume initialization authority. `NotInitialized` means CompToken has not authorized this vault. MockWorkOracle additionally uses `InvalidAccount` for zero recipients, `ZeroAmount`, and `InsufficientRights`.

Feed errors are `InvalidConfiguration`, `UnauthorizedReporter`, `UnauthorizedRelayer`, `InvalidAttestationChain`, `InvalidAnswerType`, `AlreadyReported`, `ZeroValue`, `ExcessDeviation`, `InvalidSignature`, `InvalidTimestamp`, `ExpiredAttestation`, `StaleAttestation`, and `ReplayedAttestation`. InvalidSignature includes malformed length, high-s signatures, invalid v, and a signer other than the configured attester. Relayer, payload-chain and answer-type policy failures revert before consuming the request or updating the feed.

Vault operation errors are `ZeroAmount`, `InsufficientCollateral`, `InsufficientRights`, `UnsafeCollateralRatio`, `HealthyPosition`, `ExcessRepayment`, `UnexpectedCollateralReceived`, `StaleFeed`, `InvalidPrice`, `PositionNotMarked`, `GracePeriodNotElapsed`, `MarkExpired`, `UnderwaterPosition`, `DebtCeilingReached`, `WorkCeilingReached`, `PriceDivergence`, and `InvalidBonusShares`. PriceDivergence rejects a gap beyond the primary-relative bound; InvalidBonusShares rejects combined bonus shares above 10,000 basis points. UnexpectedCollateralReceived detects an unsupported collateral deposit whose balance increase differs from the requested amount. External token/oracle/feed reverts propagate; ERC-20 custom errors include balances and allowances. SafeERC20 false returns produce `SafeERC20FailedOperation(token)`. Reentry produces `ReentrancyGuardReentrantCall`. A reverted transaction rolls back position changes, work credits, token supply, and emitted events together.

Suggested frontend sequence: approve the desired IMD deposit, deposit, check feed freshness, divergence, and collateral headroom against `minCR()`, then borrow with `mintCOMP`. Work minting uses `mintFromWork` and available rights independently of collateral. On repayment, call repay directly from the indebted wallet and withdraw any newly available collateral. Show debt-free ratios as debt-free rather than rendering uint256.max as a percentage. Display primary and spot prices, their divergence, NHI, the effective minimum ratio, accrued debt and fees, total bad debt, and the stored grace countdown and mark expiry. Refresh balances, rights, feeds, and position after each confirmed transaction. Restrict the grant-rights panel to `MockWorkOracle.deployer()` and show Sepolia only.
